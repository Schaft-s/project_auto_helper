# АвтоНапарник — план разработки агентами, версия 2

**Статус: готовый пакет спецификаций, не работающее приложение.** Дата: 20 октября 2026 года. Он создан заново из двух сохранившихся Markdown-файлов и исследования первичных источников. Утраченный архив не выдаётся за восстановленный оригинал.

Цель — один проект для двух курсов: дообучить небольшую автомобильную LLM и встроить её в размещённый AI-сервис с реальным MCP. Сильный маршрутизатор вызывает два инструмента: поиск сведений NHTSA и консультацию по техническому документу через RAG + малую модель.

## Начать здесь

1. Прочитать [AGENTS.md](AGENTS.md), [продукт/курсы](docs/01-product-and-courses.md), [архитектуру](docs/02-architecture.md).
2. Открыть [backlog](backlog/tasks.json), [приёмку](backlog/acceptance.json), [матрицу требований](backlog/requirements.json) и [ранний milestone воркшопа](backlog/milestones.json).
3. Начать T01–T03 (M0). Не считать документацию провайдера живым MCP/GPU smoke.
4. Затем собрать M1 — размещённый интерфейс с реальным NHTSA MCP, параллельно готовя разрешённый технический корпус.

## Проверка этого пакета

Нужен Python с Pydantic 2.x; версия, на которой проверено, указана в отчёте. Зависимость можно установить из requirements-spec.txt в собственной среде.

```bash
python validate_bundle.py
```

Проверяются парсинг JSON, DAG задач, ссылки на требования/acceptance, совпадение экспортов со схемами Pydantic, положительные и отрицательные примеры, локальные Markdown-ссылки. Семантическая правильность автомобильных рекомендаций, реальные внешние сервисы и права владельца данных этим скриптом не проверяются.

После намеренного изменения contracts/models.py:

```bash
python validate_bundle.py --export
python validate_bundle.py
```

## Что уже сделано и что пока нет

Сделано: разобраны два исходных плана; проверены первичные источники; прочитаны два официальных HTTP JSON NHTSA; создан и проверен пакет. При HTTP-чтении ACURA RDX 2012 получены две кампании и 15 жалоб; это временный результат чтения API, не тест MCP или полноты данных.

Не выполнены: MCP handshake/tools calls; вызовы платной сильной модели; аудит реальных КСО; запуск GPU; обучение; приложение; публикация репозитория/сайта; метрики модели. Для каждого пункта есть задача и проверяемый выход.
