АвтоНапарник

От симптома и известной машины — к фактам NHTSA, обсуждениям механиков и сборочным проверкам. Без ложного диагноза.

Открыть бота @autolover_test_bot

Задача, пользователь, MVP

Кто

Автовладелец и механик. Режим owner / mechanic меняет язык, не снимает ограничения безопасности.

Сценарии

Известные проблемы NHTSA · симптом после ремонта · сборка панелей/фар · смена машины в диалоге.

Границы

Telegram + MCP + RAG + specialist. Нет Web UI, нет SFT, нет подмены автомобиля.

Критерии готовности
  • Живой MCP-вызов NHTSA в диалоге
  • RAG со ссылкой на источник
  • Specialist на сборочный вопрос
  • Multi-turn тесты контекста и смены машины

Архитектура

Telegram → Orchestrator → OpenRouter ├─ vehicle_safety_lookup → MCP → NHTSA ├─ search_discussions → Qdrant hybrid └─ workshop_consult → Specialist (отдельный промпт) + demo corpus клипсов/панелей

Оркестратор

DeepSeek Flash · tool-calling · JSON ответ в Telegram HTML

Specialist

Специализированная модель с отдельным промптом. Планируется заменить на дообученную модель специалиста по сборке.

Политика

SRS/HV → caution. Нет диагноза. NHTSA = рынок США.

MCP-интеграция

Собственный минимальный MCP-сервер на официальном Python SDK. Оркестратор не ходит в NHTSA REST напрямую.

Инструмент MCPНазначение
nhtsa_search_recallsОтзывные кампании
nhtsa_search_complaintsЖалобы владельцев
nhtsa_lookup_vehiclesСправочник моделей (models)

Фасад приложения: vehicle_safety_lookup. Подмена Chery/Lada похожей US-моделью запрещена и покрыта тестами.

Демо и воспроизведение

  1. Открыть @autolover_test_bot
  2. «Toyota Camry 2015, есть отзывы NHTSA?» → MCP
  3. «После установки панели дребезг» → specialist
  4. «спасибо» → без повторного поиска
  5. Сменить машину в том же чате → контекст не смешивается

Локально: Docker Compose (Qdrant + MCP) → ingest → python -m autonaparnik.bot.main. Подробности в README.
